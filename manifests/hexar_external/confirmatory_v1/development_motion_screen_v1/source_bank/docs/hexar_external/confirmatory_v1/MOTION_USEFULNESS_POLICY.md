# Prospective quantitative motion-usefulness candidate

**Development candidate, not a confirmatory freeze.** Adopt a transparent communication resolution of 0.1 m for supplied sampled odometry travel: either a supported estimate expressed at 0.1 m resolution or finer, or a supported nonnegative range/bound no wider than 0.1 m. Equivalent metric units are acceptable. Preserve sampled odometry source/window scope. No motion unit is required when odometry is absent or masked.

This defines how much of a visible quantitative observation an answer must preserve to be useful. It prevents arbitrarily coarse or unquantified descriptions from winning by withholding available evidence. A tenth of a metre provides an ordinary concise disclosure of navigation travel; the choice does not demand the contract's many significant digits. It is a communication-resolution choice, not a claim about sensor accuracy or a threshold for motion, task success, physical arrival or physical causes. The selected threshold is not fitted to the original twelve-recording result, whose interface lacked this motion unit. It must be reviewed with the final acquisition domain and qualified before freeze.

Numerical support is separate. Ordinary explicitly approximate scalar presentations may differ by half their expressed quantum. Literal exactness requires equality. An approximate whole-metre value may be supported but fail required useful coverage. Approximate 0.0 m can cover a tiny nonzero sampled estimate; exact zero or physical immobility cannot be inferred. A quantified “less than 0.1 m” describes [0,0.1), is eligible when supported, and remains a sampled observation. A true [0,100] m bound is too broad for required coverage. Unquantified “some”, “little”, or “negligible” travel does not supply the required quantitative observation. Unsupported extras never erase separately correct coverage.

`motion_usefulness.py` deterministically checks separately grounded scalar/range presentations. It does not find all claims, identify their source or temporal scope, normalize arbitrary prose, or validate physical truth. Grounding and literal-exactness judgments remain separately required. `navigation_usefulness_v2.py` supplies byte-identical requirement text to the public method packet and independent packet-only reference, without editing historical packets or run sources. The strengthened baseline prompt is unchanged; both methods must receive the new common public task requirements. The baseline can satisfy them within its existing three-sentence/60-word allowance; contract realization already uses a joint outcome/diagnostic clause to preserve that allowance.

The v4 agent evaluator retains the seven-field span-aware schema and adds these explicit coverage instructions. A predeclared 96-call A/B screen uses 48 authored contrasts on the six permanently exposed v13 episodes: fine rounding, coarse rounding, narrow ranges, broad true ranges, vague travel, omission, wrong magnitude and unsupported physical immobility. Every expected support/specificity/covered-unit vector and ambiguity presence must match, and every call must return valid. Any transport failure or mismatch fails the screen; no retries or adjudication. This qualifies these authored distinctions only, not general annotation accuracy, exhaustive claim detection, full endpoint aggregation or human validation.

The previous v3 controller screen and all method/scoring results retain their original source hashes and labels. They are not retroactively re-scored. Actual equal-interface method requalification and broader operational endpoint qualification remain necessary even if the authored v4 screen passes. No confirmation cohort, alpha allocation or N is activated by this policy.
