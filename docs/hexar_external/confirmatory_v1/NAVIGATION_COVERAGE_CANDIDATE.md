# Whole-episode useful-coverage candidate for the simulated interface

This is development endpoint engineering, not a frozen endpoint or a scoring result. The existing inspected outcomes, candidate endpoint and historical packets remain unchanged. The final required-unit builder needs deterministic traceable bindings and independent evaluator qualification before admission.

The strict whole-episode failure candidate remains any unsupported material, excess diagnostic specificity, or mandatory useful-unit omission in the fixed nine-answer battery. Required units must be derived from each masked visible packet, never from its hidden scenario family or intended anomaly. The same rules apply to both methods and all three navigation-only question candidates.

Candidate mandatory units are:

- **Reported navigation outcome:** preserve the actual visible terminal software status and explicit timeout/abort. Software success must remain source-qualified if physical attainment is not established.
- **Useful diagnostic observation:** where visible diagnostics exist, preserve at least one relevant bounded diagnostic observation. A request for clearing is a request, not completed clearing. A supervisor interlock flag is an observed flag, not an assertion of battery charging or human operation.
- **Measured motion:** where a qualified motion channel is present, preserve its instrumented scope, window and substantive observation. No-motion language requires prospectively selected numerical tolerances, adequate sampling and an episode window. Unknown channels cannot become zero motion. Odometry is not unrestricted world-pose truth.
- **Visible outcome/measurement discrepancy:** where a reported success coexists with qualified no-motion observations, preserve both facts and uncertainty about their relationship. The valid manual-interlock development episode motivates this information requirement; it is retained rather than excluded. Do not require physical nonattainment unless visible goal, pose, common frame and timing actually support it.

Public static controller configuration permits optional supported source-qualified rule descriptions. Merely adding that configuration does not make every rule mandatory in every answer. If the final endpoint requires a specific relevant rule, relevance and its reference binding must be defined before output generation. Neither method can receive a reference-only hint. A configured lower-priority inhibition rule is not evidence of runtime deployment, active lock, applied command or a unique task-failure cause.

Final numeric tolerances, windows, mandatory motion/discrepancy criteria, source-specific reference bindings, unresolved-label disposition and evaluator qualification remain open. The whole-episode endpoint must protect these information units rather than allow a shorter contract answer to win by omitting visible conflicts. Contract and baseline development on this expanded interface may be unfavorable; all attempted outputs must be retained. Only after acquisition/interface qualification and endpoint engineering can paired discordance assumptions justify N or reserve decisions.
