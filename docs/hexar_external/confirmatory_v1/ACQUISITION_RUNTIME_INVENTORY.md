# Acquisition runtime dependency inventory

`runtime_closure_v1.py` builds a read-only conservative Python import inventory from the production candidate entrypoints and all captured acquisition source-bank resources. The v1 result records **109 local source/resource files**, **52 captured source-bank resources**, seven original-callback/core resource pins, and 25 nonstdlib external import names. It performs no robot, native-reader, explanation or judge dispatch.

This is a development inventory, **not** the final scientific `runtime_dependencies.json`: `complete_transitive_closure` remains false, and confirmation is unauthorized. It identifies the dependencies a final runtime binding must cover rather than substituting a manually asserted completeness flag.

The scanner follows relative/absolute imports, imported submodules, executable package initializers, constant `import_module`/`__import__` calls, and cycles. It hashes declared non-Python source-bank resources. It distinguishes host legacy module roots from the captured bank's standalone module search. Relative imports in captured development utilities receive their original package context as a conservative overapproximation, including functions that the native reader never invokes. This does not assert that these utilities can run standalone or that all discovered branches execute during acquisition.

Strict discovery rejects unresolved dynamic imports and `exec`/`eval`. Inventory mode records such sites while keeping the completeness flag false. The actual dependency walk identifies one dynamic site: the preserved callback AST loader in `analysis/hexar_external/replay.py:63`, reached through the existing packet builder. Its original upstream callback sources, source manifest and pinned CRANE core are separately hash checked. That loader captures original callback behavior with an offline capture client; the inventory does not execute it or claim that resource hashes alone qualify arbitrary dynamic execution. Its exact class-selection/instrumentation behavior still needs explicit final-adapter qualification and binding.

Python/stdlib, Docker/host OS, ROS/interface packages in the pinned simulator image, host package versions, shell/launch dependencies and any provider environments remain separate runtime requirements. External import names are a dependency list, not evidence that a package version is available or qualified. The v1 output is stored at `manifests/hexar_external/acquisition/raw_runtime_static_inventory_v1.json` and pins the candidate runtime descriptor without editing its captured bank.

Twelve focused scanner tests pass, covering package cycles/initializers, standalone bank precedence, legacy host search roots, namespace packages, unresolved dynamic code, declared original bank-package context and path containment. The inventory command completed against the actual current source bank and verified all callback/core resource pins. No alpha, endpoint, comparator, sample-size or cohort eligibility changed.

The next integrated runtime qualification must bind this local closure, the exact dynamic callback path, the actual host/image external environments and original capture-to-seal chronology. Final admission must cover those hashes in both the family scientific binding and acquisition freeze.
