# Simulated evidence interface: fairness and outcome scope

The prospective interface is **not yet frozen**. The old twelve-recording result and its packet contexts remain development evidence and are preserved. The new simulated benchmark must qualify its actual available evidence rather than assume the original bags' visibility limitations apply unchanged.

The first-party TIAGo stack supplies genuine `twist_mux` configuration: navigation input priority 10, manual-selection lock priority 100 and charging lock priority 210. Equal or higher-priority inputs can remain eligible. `public_control_source_v1/` retains the original config bytes, repository commit and image identity. `acquisition.public_context.extend` creates a separate deep-copied development packet extension supplying the same config to both methods. It makes no method call and does not mutate historical packets. The strong HX-PROMPT text is unchanged.

Static source licenses descriptions of configured rules. It does not by itself prove deployed wiring, observed rule activation, controller output, physical motion or a unique physical cause. The extension explicitly marks per-episode runtime binding as unprovided pending qualification. Supervisor flags in this simulation represent interlocks; they do not independently establish actual battery charging or human joystick operation. The prospective reference builder and evaluator must permit supported source-qualified information and must not indiscriminately mark every specific control statement unsupported. New qualification needs positive licensed statements as well as causal overclaims. Existing authored screens with unavailable governing source cannot establish this richer scope by themselves.

The corrected-image uniform v8 development set contains an important adverse case: the manual-interlock episode reported Nav2 action success while applied commands and measured odometric motion remained zero. This technically valid episode must be retained. Reported software success and measured physical goal completion are distinct propositions. Odometry is itself an instrumented measurement, not an unrestricted assertion of world-pose truth. A final physical-goal unit needs actual goal/pose/frame/time provenance and precommitted measurement tolerances.

Before freeze, supply legitimate motion/configuration evidence equally to both methods through a qualified universal projection, define its masks before derivation, and qualify source and numeric specificity. Determine which outcome/contradiction units are mandatory to keep an answer useful. Both methods must handle contradictory visible evidence; a contract cannot gain a coverage pass merely by omitting a required conflict. Neither unexplained navigation failure nor an anomalous success status can be a replacement criterion. Missing optional evidence remains unknown.

Final question bindings also need domain review: the present no-arm harness executes navigation only, while some inherited original questions refer to bringing an item and the historical source scenarios include manipulation requests. The recorded navigation task is not evidence that manipulation was requested or completed. Do not insert unexecuted skills or fabricate a delivery result. Any justified navigation-specific query adaptation must be documented prospectively, preserving the original words as historical/development references and applying the same final wording to both methods. Sampled targets labeled kitchen also need an explicit semantic goal/zone mapping before any physical-room fidelity claim.

These are development and freeze-preparation tasks, with no additional alpha, no confirmatory outputs and no change to the separately reported original HEXAR 49/54 navigation accuracy. The benchmark remains accurately described as an adapted simulated HEXAR external-validation benchmark.
