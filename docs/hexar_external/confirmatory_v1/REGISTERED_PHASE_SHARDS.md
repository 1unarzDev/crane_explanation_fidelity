# Bounded registered workflow phases

`registry_shards_v1.py` partitions a complete predeclared phase schedule into deterministic, sorted, byte-bounded and job-bounded registered shards. The versioned default is 8 MiB and 128 jobs per shard, within the executor's separate 32 MiB persisted-artifact cap. An entire registered request must fit; oversized individual requests and indices fail before namespace creation, without truncation or enlarged response caps. Defaults are candidates, not a final study freeze.

Each phase has one immutable index with the study/development binding, phase, workflow stage, full-schedule fingerprint, exact complete job list partition, every shard's raw-byte hash, canonical registry hash and byte count. Full bundle verification rejects omissions, extra shards, global duplicate identities, reordering, changed requests and noncanonical partitions. Exclusive creation retains partial namespaces rather than permitting a rerun.

The wrapper uses one persistent execution root bound to that exact phase index. Every dispatch repeats independent stage/index/root admission, verifies on-disk index and requested shard, then invokes the existing registered single-attempt executor in its fixed shard subdirectory. Closed outcomes reproduce without provider dispatch; an interrupted durable claim closes as indeterminate without reissue; per-job locks retain the active-call protection. Sharding changes storage only: aliases, requests, judge policy, parsing, raw archives and semantic endpoint are unchanged.

Qualification covers deterministic byte/job boundaries, >1 MiB total schedule with separate 1 KiB response cap, complete identity preservation, cross-shard duplicate detection, exclusive creation, denied/revoked admission, root/index/shard changes, persistent recovery and retained crash disposition. These synthetic tests and any read-only decomposition of exposed development registries establish engineering behavior only. They do not retrospectively preregister development or qualify a served model.

**Final admission remains required.** It must pin the actual execution root and exact phase index, freeze bounded settings, validate complete request/dependency/provider bindings and enforce chronology: neutral references and methods before method generation; opaque initial judge jobs after sealed method outputs; C jobs only from the frozen disagreement rule. The caller cannot provide a permissive callback for confirmation. This wrapper has no independent scientific authorization and is not yet wired as the final prospective semantic adapter. No existing successful executor, active runner, endpoint, prompt or scientific analysis is modified.
