# Fixed integrated raw-adapter development qualification

Before any launch, commit the v19 development plan, runtime descriptor, source/import inventory, development-exposure snapshot and declaration. This is an engineering qualification of the actual capture/native/archive/selection adapters. It never admits production or semantic confirmation and does not alter alpha, endpoint or N.

Exactly six new development primaries are attempted, one per family in the existing interleaved order. Their independently drawn 256-bit master seed and derived seed namespace differ from confirmation schedules. Twelve allocated development identities/seeds (six primaries and six unused reserve placeholders) are permanently excluded. The reserve placeholders allow the existing scheduler to close every primary even if a primary is technically invalid; the qualification adapter expressly forbids dispatching a reserve. After the sixth original disposition, stop regardless of validity. No robot or native-reader retry, replacement, method generation, semantic judgment or p-value is permitted.

The runtime retains the already qualified image, captured physics source bank, ROS domain 70, offline network namespace, 3 CPUs, 5 GiB memory, 6 GiB memory-plus-swap, 1 GiB shared memory, 230-second episode timeout and 180-second native-reader timeout. It invokes the same bound shell/driver, host capture implementation, phase-aware reader, deterministic packet/reference construction, operational validity predicate and raw archive/selection code used by the production candidate. Only explicit acquisition phase, development identities, roots and independent committed development admission differ. Simulator/physics source bytes are unchanged. Never relabel development receipts as raw confirmation.

The admission checks declared local sources, configuration/plan/policy pins and existing bank bytes before each operation. It verifies the unchanged baseline development inventory while allowing only declared new primary receipts under the same declaration binding. The old HEXAR recording hashes remain excluded. The capture root remains the development acquisition directory so subsequent exposure inventories find all attempts, including failed launches. Production admission remains independently fail-closed and rejects development schedules.

Each dispatch has an exclusive scheduler claim, host launch claim and owned Docker CID. Native input is read-only with one reader claim. Every primary receives a hash-bound raw archive and outcome-blind validity receipt. Interruption follows the same conservative invalid/no-reissue disposition, without robot or native replay. Semantic contamination is not replaceable technical invalidity.

Pass the scoped screen only if all six original primary attempts satisfy the existing operational technical predicate, all six archives/receipts agree with the scheduler, the source bank and declared files remain unchanged, and all six distinct original captures can pass the same selection function under the explicit development phase. In that case produce a **development-only archive seal**, never the scientific raw cohort seal. Preserve all failures and partial artifacts otherwise, with no repair of validity labels. This screen does not establish a population effect, final N, invalid-rate guarantee, external provider stability, complete production qualification or confirmation permission.

The pipeline's default raw-confirmation modes retain their existing interfaces. Shared adapters validate explicit raw/development phase; development use requires a separate committed admission context. Focused phase tests protect against treating the newly exposed data as confirmation.

The original offline callback loader reads two upstream files maintained outside Git. The declaration therefore pins their original bytes and identical committed copies under `captured_callback_source`; each development admission verifies both representations. This preserves original provenance and gives the AST-loaded resources an auditable committed archive.
