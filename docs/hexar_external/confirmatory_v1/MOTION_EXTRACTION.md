# Native motion/action extraction qualification

`analysis/hexar_external/acquisition/extract_motion_v1.py` is a separately scoped pure bag extractor. It reads only recorded ROS messages and metadata, never family, seed, intervention, planned coordinates, driver reports or explanation labels. Output follows `event_id/topic/recorded_ns/value`. Bag receipt times remain receipt times; source header stamps and frame identifiers are separately preserved. Exact source types are checked before deserialization, and nonfinite positions, velocities or quaternions fail extraction. Numeric bounds and source hashes are auditable in the versioned qualification/provenance files.

Normalized channels:

- `/mobile_base_controller/odom`: recorded odometry header/frame, child frame, pose/quaternion/covariance and twist;
- `/cmd_vel`: recorded unstamped input linear/angular commands;
- `/mobile_base_controller/cmd_vel_out`: recorded stamped controller-output linear/angular commands;
- `/navigate_to_pose/_action/status`: genuine goal UUID/stamp and numeric software status;
- `/goal_pose` or `/hexar_acquisition/navigation_goal`: actual recorded pose/header/frame, when present.

All six corrected-image v8 bags contain odometry and both command streams, and normalize without private metadata. **None contains action status or goal pose.** Humble rosbag2 excludes hidden topics unless `--include-hidden-topics` is supplied, even though the earlier command explicitly named action status. An action goal is normally transported through the `send_goal` service, not a goal-pose topic. The installed Humble action client has no `configure_introspection`, and installed rosbag2 records topics without service-event support. Consequently v8 goal and status remain unavailable; private plan coordinates and driver status must not be substituted into the visible packet. Original task/skill logs remain separately usable recorded software evidence.

A fresh, separately seeded v9 development acquisition instruments the actual submitted `PoseStamped` goal on `/hexar_acquisition/navigation_goal` and enables hidden-topic recording. The publication is from the same goal object immediately before the actual action send, with recorder discovery checked. This is task request provenance, not proof of goal acceptance, measured arrival or physical success. Software status remains separately obtained from the actual action-status stream. Old bags and extraction receipts are untouched. The focused run tests recorder viability rather than broad method performance.

Odometry estimates motion rather than providing independent physical ground truth. Controller output commands do not prove applied torque or movement. Coordinate comparison between an odom-frame pose and a map-frame goal requires a separately qualified TF policy; this extractor invents neither a transform nor an arrival claim. Unstamped commands have receipt-clock information only. Sampling rates, gaps, accumulated path distance, velocity bounds and task-window selection need a frozen downstream summary procedure. The valid manual-priority v8 software-success/no-odometric-motion discrepancy remains preserved. No method or judge calls are made.

The focused v9 recording completed with one actual submitted goal message in `map`, three genuine action-status messages and software codes 2 (executing), 3 (canceling) and 5 (canceled). The nominal-family navigation timed out and was canceled; that adverse valid outcome is preserved. The goal remains a recorded request rather than a measurement of physical arrival. This demonstrates Humble recorder viability after enabling hidden topics and publishing the exact request object. Its source snapshot, goal/status provenance and raw hashes are preserved separately from v8.

The normalized v8 events contain finite stamped odometry in `odom` with `base_footprint` child frame; applied command headers have their recorded frame (which may be empty), and no fabricated header is added to unstamped inputs. Provenance includes exact topic/type/message counts, receipt/stamp ranges, original SQLite/metadata hashes and normalized event hash. The qualification report includes per-axis finite numeric bounds without clipping. Original v8 motion and historical callback artifacts are unchanged.

`motion_context.py` supplies a separate development recording-scoped numeric projection. It applies the diagnostic-removal mask before deriving summaries, removes odometry/command channels under that mask, and retains actually recorded requests/statuses. Intact and irrelevant-removal projections agree on the six v8 native bags. Odometry requires one nonempty frame, finite XY coordinates and strictly increasing measurement stamps. Receipt and measurement windows, message count, maximum sample gap, sampled XY path length and displacement remain explicit. Linear and angular command norms are reported separately in their own units. Neither a transform nor goal arrival is inferred. Numeric zero, unavailable data and small drift remain distinct.

`motion_summary_qualification_v1.json` binds the native event/provenance hashes and all three summaries for six development episodes. In particular, manual-interlock sampled path distance is approximately 0.00000464 m and charging approximately 0.00001685 m; they are small recorded drift, not literal zero path length. Final no-motion thresholds and adequate sampling/window criteria remain unset. Existing displacement summaries, raw evidence and old method results are unchanged. This projection has no provider calls and does not yet qualify references, mandatory units, contract rendering or evaluation.
