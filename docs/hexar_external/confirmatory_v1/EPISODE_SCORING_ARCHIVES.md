# Bounded per-episode semantic scoring archives

The complete six-episode v3 artifacts reveal an acquisition-scale constraint beyond request registry sharding. A direct linear projection to the conditional N=3,072 planning point would make the public scoring plan about **1,912 MiB**, the neutral reference registry **671 MiB**, method outputs **36.5 MiB**, and closed dispositions **53.1 MiB**. These are measured size projections, not new recordings or a sample-size decision. The existing 32 MiB artifact loader cannot admit those monolithic objects.

`episode_scoring_archives_v1.py` partitions reference registries, unique plans, outputs, public A/B(+C) plans and private linkage by the independent episode. Each archive retains both methods, all nine battery cells and six unique requests per method. It uses the unchanged blinding, disagreement-only C, adjudication, required-unit/specificity components and least-favorable unknown mapping. A cohort manifest contains hash-bound episode pointers rather than copying full evidence/answer payloads. Bounded objects fail before creation rather than truncate; original archives are exclusively created and independently hash-checked on read. Episode/method/query/evidence identities never merge across episodes.

The fixed master blinding key derives a separate HMAC key and shuffle namespace per episode. This is an implementation candidate: prospective key storage, cross-episode dispatch ordering, complete cohort validation, stage chronology, final provider binding, streaming execution and terminal analysis admission must still be frozen and qualified. The pure builder/writer has no provider backend and every archive remains `dispatch_authorized=false`, including objects carrying a confirmation phase label. A label does not authorize confirmation.

A retained development replay partitions the already-exposed six-family v3 outputs and original A/B(+C) outcomes. It first and last reproduces all 217 original raw/journal attempts. It preserves every per-request semantic disposition, expanded battery row, whole-episode endpoint and descriptive paired count `[2,0,4,0]`. It generates **zero** answers or judgments and computes no p-value, interval or confirmatory effect. The largest complete episode artifact is 1,203,473 bytes; the six-episode pointer index is 1,689 bytes. A separately labeled synthetic N=3,072 pointer-capacity test occupies 468,155 bytes; those rows are not acquired episodes or statistical N.

The replay's initial loader failure occurred before creating a destination or calling any provider: it looked for outcomes under direct job-ID directories instead of the hash-bound single-attempt journal. The retained failure receipt records that mistake. The corrected replay reads the existing closed journals and verifies original raw evidence without redispatch. Exact hash-matching source snapshots that produced the replay are archived. Subsequent reader hardening verifies size before loading and requires hexadecimal binding/pointer hashes; focused tests verify current code against the retained archive. No underlying semantic outcomes or endpoint rules changed.

Twelve focused tests pass for bounded roundtrip/tamper handling, phase isolation, exclusive writes, no truncation, duplicate episode/path/hash rejection, path containment, complete paired battery construction, opaque public payloads and blinding namespaces. This closes a representation gap and establishes retained computational equivalence. It does **not** qualify actual sharded provider dispatch, guarantee all possible outputs fit, authorize a new semantic adapter, freeze N or supply an immutable served model. Confirmation remains gated by the independently frozen H1/H2 family and full preconfirmation audit.

Full-suite validation: 480 tests passed; the existing missing legacy development-packet fixture failed one test. The current-reader receipt separately binds the size/hash hardening and its tests, while preserving the exact sources that originally produced the replay. No replay artifact or semantic label was overwritten.
