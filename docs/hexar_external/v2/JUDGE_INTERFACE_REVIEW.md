# Judge interface issue found during development

V2's support qualification passed 24/24 atomic labels and 40/40 fields in both passes. During six-family development, some otherwise schema-shaped returns change the form's fixed `false_premise_handling=NOT_APPLICABLE` value. The main validator rejects them with `false-premise label must remain not applicable`. These returns are retained as technical/protocol failures; they are not semantic failures or successful abstentions, and no failed job is retried.

Read-only source review identifies an interface tension: the main prompt says “For an applicable nominal/success question, distinguish explicit false-premise rejection from acceptance or partial handling.” The return schema offers multiple premise labels, while `validate_return` requires the NOT_APPLICABLE sentinel when the form sets it. The external endpoint does not score this premise field separately; its atoms/coverage/scope already distinguish supported outcome from unavailable subjective motion/delay conclusions. The released original questions do include nominal/success episodes and subjective motion premises, unlike the neutral questions in the synthetic external qualification.

This is a development measurement issue, not a method deficit. Keep the current queue and failed returns unchanged. Do not normalize, suppress or reinterpret its raw labels. Before held-out activation, review a prospective interface correction using current pipeline-supported form/schema behavior and a bounded fresh structural/support qualification if required. Preserve endpoint, references, all methods and evidence. A fix must apply to every method and cannot target known comparative failures. Do not merely lower a qualification gate or the declared 90% technical admission threshold after seeing that it fails.

The ordered release checks pilot technical completion before freezing reserved execution. If it fails, no reserved answers are generated. This document is a source-level diagnosis, not an authorization to rescore the v2 pilot.
