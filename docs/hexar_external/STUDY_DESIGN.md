# Prospective development design — 2026-09-30

This is a development declaration, **not a confirmatory activation**. The released navigation category was selected before comparative failure inspection: cases 5–10, all six situations, 18 bags, three original questions per bag. Recording repetition 1 is development (six bags); repetitions 2–3 are reserved (12 bags). No mechanism family is held out. The first inspected development recording is `bagfile_6_1.bag` (`dev001`). Historical released labels are category A; fresh upstream-prompt adaptations are category B; removal experiments are category C.

The sole candidate primary endpoint is the recording's mean binary success over the three original questions × three evidence conditions, equally weighted within a recording. Success requires the packet-specific supported explanation or useful partial facts, no material unsupported causal/mechanism assertion, and appropriate treatment of unavailable conclusions. Recordings receive equal weight; the six declared situation families receive equal total weight. Freeze every packet reference, materiality decision, endpoint-role map, question and condition weight before reserved output generation. Coverage requires useful facts, so blanket abstention fails. Correct supplemental facts supported anywhere in the permitted packet are allowed.

HX-CONTRACT versus HX-PROMPT is primary; HX-CONTRACT versus HX-ORIGINAL is secondary. New automated labels will be called agent-assessed. Required units and support judgments are evaluator artifacts independent from production contract logic. Existing human labels are used only to reproduce historical metrics.

HX-ORIGINAL executes the pinned navigation callback bodies and unchanged navigation prompt, with a fresh instance per transformed replay. The offline API/harness is a declared fresh-model adaptation, not the historical phi4 realization or end-to-end HEXAR. HX-PROMPT corrects unsupported symptom-to-cause examples and uses the frozen calibration text, common primitive facts and availability. HX-CONTRACT adds the pinned main CRANE ontology/planner/constrained-realizer interfaces, using a small public navigation ontology and the same primitive facts. It deterministically replaces navigation realization; it is **not a post-hoc free-text verifier**. Both new methods allow three short sentences, at most 60 words. The original retains its one-sentence purpose; only the primary contrast has equal richer formatting.

The first development mask removes `/joy_priority` and all alternate manual-indicator log/error representations **before** state derivation. Fresh state preserves `None` for absent manual evidence. The irrelevant control removes recorder housekeeping logs. Task status and timeout/progress traces remain. The last recorded manual state can support a bounded state statement, but the supplied release does not establish the robot controller's governing inhibition code; even intact data does not establish a unique physical cause. This is deliberately conservative about causal attribution, not a substitution of scenario gold for packet support.

Native parity checks a real ROS Humble DDS replay at 1× using deserialized original inputs and original callback/task bodies. Receipt clocks are traced/frozen at callback entry, then supplied identically to the offline replay. This establishes serialized-input/state/window/prompt parity under declared instrumentation, not equivalence to historical timing, selector behavior or lifecycle/action scheduling. Subsequent deterministic replay uses bag receipt timestamps rather than pretending to recover historical replay wall clocks. No selector is redesigned; the experiment is restricted to the navigation component.

No confirmatory alpha is allocated to HEXAR. The actual ledger protects 0.02 replication and leaves at most 0.01 future discovery already awaiting the main study freeze. A new allocation requires coordination with the publication owner; this work must not edit the ledger. With only 12 reserved recordings and six known families, repeated masks/questions cannot create physical N. Pilot discordance and a family-aware precision/power analysis must precede any confirmatory design. If those gates cannot be met, use a descriptive external evaluation and report uncertainty without a superiority claim. Never switch family clustering because significance is lost.

Model provenance: exact historical `phi4:latest` artifact is unresolved and neither released endpoint nor local Ollama is reachable. The bounded development generation candidate follows the retained main B2 pilot's explicit `gpt-6-sol`, high effort, ephemeral no-tool CLI binding, identically for the two model-backed methods. This is a hosted model identifier, not a weight hash; backend immutability is unverified. Contract realization makes zero model calls and reports that resource/template tradeoff. Generation changes are adaptations, never evidence of improvement over old phi4 answers.

Current support annotation binding comes from `manifests/study/evidence-calibration-agent-qualification-disposition-v1.json`: Astra/high, exact v4 task, two isolated passes, disagreement-only adjudication, no quality retries. Before scoring these new manual-state/timeout categories, perform a bounded external exact-task qualification and independent packet-reference review. The v2r2 stance/polarity pass does not qualify endpoint roles. No development prose inspection is a qualified endpoint label.

Expansion is gated on this first recording's completed evidence-flow inspection, native parity, independent support references, qualified measurement, and coordinated model quotas. The complete declared six-family set remains the intended population. No charging/localization/dynamic scenario is dropped based on observed method performance; no family-specific mask is asserted valid until actual bag-content and removal-closure audits pass.
