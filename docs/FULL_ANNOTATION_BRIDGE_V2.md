# Full RoboBoat annotation bridge v2

This additive development bridge admits the actual full-CRANE v2 response schema. It preserves every prior response, renderer declaration, extractor freeze, support record and endpoint definition. It neither promotes the method-reuse sensitivity to confirmation nor changes the complete supported diagnostic answer endpoint implemented by material workflow v3.

## Source admission

`analysis/run_roboboat_full_population_inventory_v2.py` prepares an immutable blind text bank, response join and full response accounting ledger from `run_roboboat_full_population_responses_v2.py` declarations. All completed snapshot entries remain in accounting, including absent terminals, orphan answers, failed B2 calls and missing answers. Output selection does not depend on physical outcome or explanation quality.

Admission verifies the real v2 response declaration, exact method source closure and immutable source snapshots, registered geometry/ladder identities, and exact generation intent. A B4 answer must match its terminal `B4_candidate`, retained output binding, zero-model method marker, original execution intent, exact generation/source-snapshot provenance and full-pipeline binding. The bound full pipeline is regenerated from the original staged sources and original visible packet using the declared full adapter; equality includes facts, plan, numeric bindings, candidate, audit and final answer. No legacy renderer certificate or fabricated legacy declaration is used to bypass admission.

B4 generated before a B2 provider failure remains admissible through the retained candidate/full-pipeline bindings; no successful B2 call is presumed. Orphan outputs without a terminal are retained and excluded from annotation, with their missing-terminal slot kept in accounting. Configuration tolerance, clock and fixture-status fidelity remain the responsibility of the separately audited full adapter. No evaluator or annotation records are staged into explanation generation.

Inventory records bind their adapter, adapter tests and the unchanged generic extractor execution source. The bank's `inventory-binding.json` names the actual inventory declaration for subsequent support preparation. Generic extraction execution receives that genuine v2 declaration unchanged: two independent qualified passes, at most two workers, the transport's 300-second deadline and zero quality retries. Identical texts can share extraction work; instance joins and geometry identities remain distinct.

## Support and review

`analysis/run_roboboat_full_population_support_v2.py` verifies the immutable inventory declaration, bank, response accounting and every admitted response source/provenance again. It requires all available answers from the snapshot; failed or missing baseline slots do not disappear. Each available source text requires both exact retained extraction passes and a complete faithful project source review before the unchanged material workflow v3 builds a blind support packet.

Support execution reuses the existing qualified two-pass annotation/adjudication runner without changing its packets, method identity or scoring semantics. It uses two concurrent packets, a 300-second deadline and no quality retry. Judge packets carry the existing visible-evidence/answer forms; full method/source provenance stays in the evaluator join. The support declaration binds its adapter/test and the new release adapter/test before annotation begins.

## Descriptive release

`analysis/summarize_roboboat_full_population_support_v2.py` requires every declared available support packet to finish and receive a full source/citation review binding both raw passes, agreement and final decisions. Missing/failed support, incomplete citation review, absent decisions or unresolved claim/unit/limitation decisions refuse release. The inherited narrow exception for an explicitly recorded unresolved `highest_asserted_abstraction_level` remains secondary-only; it cannot hide an unresolved primary decision.

The output retains whole-answer labels, every atomic support label, materiality and required-unit/limitation decisions, raw agreement/disagreement data, and secondary abstraction issues. Every declared question-method slot appears. Missing or failed response generation receives sensitivity bounds `[0,1]`, never a fabricated scored label. Method totals use the full snapshot denominator and expose adverse/favorable success totals; paired differences preserve the corresponding bounds. Annotation/extraction failures cannot be omitted to produce a selective favorable bank.

Equal-weight descriptive geometry means and within-geometry discordance counts are emitted only when both registered variants, all three evidence levels and both methods have complete source-reviewed decisions. Six questions count as one geometry. Partial/missing geometries are listed separately and add no complete geometry count. Complete geometry summaries expose average B2/B4 success, paired mean difference and positive/negative/tied geometry differences. They produce no p-value or inferential activation. Confirmation N, replication N and consumed alpha remain zero.

## Commands

Prepare/run the inventory using the same CLI argument names as the generic predecessor, with the new inventory script. Prepare/run support with `--bank`, `--response-declaration`, `--response-root`, `--output-root` and `--declaration`, using the new support script. After actual extraction source reviews and actual support citation reviews, use the new release script with `--declaration`, `--root` and a fresh `--output` path. Retained failures and unresolved intents are never reissued by these commands.

Validation uses construction packets, mock provider returns, synthetic extraction/source reviews and synthetic annotation labels to test actual source admission, shared executor behavior, review gates and endpoint mapping. Those labels validate software only and are not empirical study scores. No provider calls, GPU captures or real answer scoring were executed while developing this bridge.

Focused verification: **49 passed**, including 25 new bridge tests and 24 predecessor inventory/support/release regressions. All three new adapters also pass Python compilation.

## Credential-safe execution override

The first real full-method inventory binds `roboboat_safe_annotation_execution_v1.py`, the additive safe transport, and five transport/setting/no-retry tests before any extraction calls. The helper executes exact qualified v5 atomizer bytecode with a private globals copy replacing only its transport call. Support replaces only the runner on each newly constructed per-packet caller. Qualified source files and shared module globals remain unchanged. Prompts, schemas, models, tool policy, two passes, 300-second deadline, and no-quality-retry rules are preserved. Timeout command text is never serialized; partial process output is sanitized. A provider credential in a final return is excluded as a technical failure. This is an operational safety amendment, not an endpoint or method change.
