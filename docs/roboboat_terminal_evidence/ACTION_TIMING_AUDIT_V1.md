# Retained stale-action audit and next probe

Both development captures fail the existing strict action gate: geometry 42004-00005-v1 has one stale rejection and v2 has four. Both have zero stale observations and accepted-only maximum source-to-application lag of 9 and 8 ticks, respectively. This does not establish a cause or a repair. Replaying the retained v1 result with `assert result["staleActions"] == 0` returned exit 1 and the observed count 1. It reproduces the retained failure verdict, not physical callback scheduling.

The exact source contract rejects when application tick minus the source tick exceeds 10. For these ROS commands the source tick is rounded from the forwarded header stamp divided by fixedDeltaTime. The fixture receives unstamped Twist and replaces its output stamp with its own newest delivered odometry; this is not proof of Nav2 observation choice. ROSConnection dispatches incoming messages and subscriber callbacks in Update after its network reader enqueues them. The adapter stores the callback receipt in a single latest-value mailbox and consumes it in FixedUpdate. The accepted timing summaries omit rejected receipt timestamps; frame stale increments report sensor observations only.

Ranked falsifiable hypotheses are: old selected odometry before fixture forwarding; fresh commands aged in DDS/endpoint/TCP or Unity Update dispatch; unusually delayed rejected mailbox consumption; or episode clock/tick conversion offset. The audit JSON records a discriminating prediction and falsifier for each, exact source seams and hashes of 13 sources and 16 retained physical artifacts.

The next probe should retain only bounded command timing events across four boundaries: Unity odometry publish, fixture odometry delivery/command forwarding, Unity network enqueue/subscriber callback, and gate application decision. Capture all rejected receipts plus a bounded pre/post ring of accepted and overwritten receipts. Include raw stamps, episode, local sequence, frame, simulation tick, fixed step, gate limit, decision, monotonic times, queue length and dropped-event counts. Do not add command values unless needed to disambiguate identical-stamp messages. Preserve the original output stamp, payload, subscription QoS, controller, fixture callback scheduling, .02 physics step, .04 catch-up cap and10-tick gate. Correlate cross-process commands by an out-of-band ordered forwarding ledger plus exact serialized-byte hash, raw stamp and occurrence index; identical stamps alone are not unique. Establish monotonic source stamps and complete forwarding/delivery counts before treating ordered joins as exact. Never add identity fields to the task payload merely for tracing. Writing should be buffered outside the gate lock and never await or flush from callbacks. Cross-process monotonic times must not be directly subtracted without an explicitly measured clock mapping; simulation stamps and per-process intervals provide the initial decomposition.

A sidecar can measure fixture delivery ages and public topic receipt but cannot observe the exact rejected gate receipt or network queue residence. Existing accepted-action observers cannot recover rejected actions. A fully discriminating probe therefore requires a separately versioned instrumented build/fixture namespace with a receipt-decision observer at the actual gate and a timestamp token carried from socket completion to callback. None was implemented or launched here because existing sources and live builds are bound. New adapter files alone cannot truthfully claim to expose that absent event.

Run a short targeted physical pilot using the same failed geometry and unchanged gates after the new instrumentation is separately bound; do not repeatedly collect 340-second runs with counters alone. First require complete event accounting: received=overwritten+consumed+pending, consumed=accepted+rejected, gate counts match terminal counters, and rejected rows retain all timestamps. The pass/fail repair loop remains staleActions==0 together with the full strict validity gates. Use events to distinguish mechanisms before any single-variable repair trial; an instrumented pilot without a rejection is informative about normal timing but does not resolve the failed mechanism.
