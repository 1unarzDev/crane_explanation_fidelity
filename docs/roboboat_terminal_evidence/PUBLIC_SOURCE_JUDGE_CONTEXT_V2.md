# Complete common source context for development judging

The earlier public-context amendment supplies configuration provenance but not the complete common robot/helper source files. Once both methods receive those files, a source-level statement can be supported even if it is absent from the compact runtime packet. Judges must receive the same common source context to avoid penalizing such statements as unsupported. This additive builder does not change old packets, answers or labels.

`roboboat_public_source_judging_v2.py` verifies a current-version common interface manifest and requires its evidence.json to match both original blind forms exactly. It then adds all41 reviewed common source files plus four common configuration/scope/basis inputs, preserving exact UTF8 bytes and hashes. evidence.json is already present as robot_visible_evidence and is not duplicated in the source context. Both independent judge payloads and disagreement-only adjudication receive identical45-file context. The original response text, evidence, atomic inventory, required coverage units and limitations stay unchanged.

The scope states that compiled source correspondence does not establish runtime scene wiring, internal observation consumption, external/reflected semantics, deployed Nav2 authentication or physical actuation. Source statements and configured settings can be supported while runtime causal claims remain unsupported. Treatment modules/catalogs, raw episode logs, method identities and evaluator joins are excluded from the common source context. In-packet hashes check consistency only; preparation receipts authenticate the actual common manifest, source snapshots and complete runtime builder closure. A later qualified runner must verify that receipt before submitting a packet.

Nine construction tests passed. They check equal context for both judges/adjudication, unchanged core fields, exact current source set, wrong-evidence rejection, changed/missing source bytes, identity leaks, mismatched adjudication, immutable preparation, omitted runtime closure, and rejection of altered source text even when its in-packet and outer file hashes are recomputed. Construction tests use structural fixtures only; those fixture inventories are never judged or scientifically scored.

A separate12-case source-scope construction candidate is prepared at `artifacts/roboboat-source-judge-qualification-v2-candidate-001/`. Its blind inputs contain only common public sources/evidence and the candidate claim. Its root source-audited expected labels stay in a separate evaluator-only key. Six cases concern supported software/configuration statements, four insufficient runtime-consumption/timeline/actuation claims and two contradicted configuration/authentication claims. All12 inputs retain exact hashes and omit evaluator labels or method joins. This supplements the earlier complete-supported-diagnostic-answer qualification cases; it does not replace endpoint reliability validation with easier source-fact classification.

The preparation is unexecuted and unqualified. It authorizes no model calls, releases no scores and adds zero independent N.
