# Full CRANE marine adapter v2: development readiness

This additive candidate closes the v1 fixture-timeout and governing-configuration observation gaps. It is development machinery, not a frozen confirmatory method, a new scored answer bank, or evidence of superiority. Existing v1 outputs and declarations remain unchanged.

## Implementation and evidence boundary

`analysis/roboboat_full_crane_v2.py` uses the static `configs/roboboat_claim_contracts_v2_development.json` catalog, validated v2 robot-visible packets, the actual shared `maximal_supported_diagnosis.diagnose` planner, and `realize_evidence_calibrated_explanation.realize` verifier/local repair. Realization remains deterministic, zero-model and closed-template. The output schema, question-contract identity and plan identity explicitly declare v2.

V1 has no injectable catalog/status seam. V2 therefore retains a separate builder derived from the v1 builder, rather than temporarily replacing a timeout with an invented action status. Inherited kinematic calculations, witness selection and scope contracts are unchanged. Tests compare normal succeeded/aborted/canceled outputs against v1, excluding only the new observations; inherited approved claims, numeric values and source bindings match exactly.

The original validated packet remains the provenance unit. Every numeric slot retains its JSON pointer or certificate computation, original canonical packet hash and original evidence reference. Condition and fact hashes bind that original method packet before the shared planner runs. The configuration digest reported in the visible packet is retained; this adapter does not independently fetch or authenticate external configuration bytes. Any experiment source closure must additionally bind the collector and configuration source files.

## New static contracts

- **Fixture timeout:** “The navigation fixture reported timeout.” A separate required limitation states that timeout does not establish a terminal ROS action result, cancellation or docking failure. Missing return/post-result observations yield unknown docking support; the generic planner's `KNOWN` meta-status is never physical completion. For the current collector, timeout means no terminal action result was received. Reference observations may support point measurements, but a recorded result receipt, receipt-aligned reference or nonempty post-result stream contradicts that timeout scope and is rejected.
- **Configured observations:** exact visible `xy_goal_tolerance`, `yaw_goal_tolerance`, `trans_stopped_velocity` and `rot_stopped_velocity`, each independently bound to its `/configuration/` pointer. Missing values are withheld; nonfinite, negative, boolean or nonnumeric values are rejected. Settings remain observations even if the reported plugin changes. No contract asserts that a plugin consumed them, that its particular algorithm operated, or that a threshold caused stopping.
- **Separate public requirements:** exact fixed dwell, position, heading, speed and yaw-rate requirements, bound to `/task/` pointers. Public task limits remain the bounds for kinematic checks, even when configured navigation tolerances differ.
- **Receipt-clock observation:** a recorded client receipt may expose its finite nonnegative fixture-monotonic wall time. The contract explicitly distinguishes this from the ROS-header sample clock and first post-result sample anchoring the dwell. The adapter neither subtracts unlike clocks nor substitutes receipt time for a sample anchor. Unsupported recorded receipt clocks/times are rejected; unavailable receipt evidence produces no receipt claim.

Arbitrary unregistered action statuses remain rejected. Unapproved physical-cause and cancellation injections are removed by the shared realizer; missing required information and altered numeric slots are repaired from the supported plan. No hidden evaluator, answer certificate, caller-supplied fact bundle or plan is admitted through the packet.

## Verification and remaining work

Validation: `PYTHONPATH=analysis python -m pytest -q tests/test_roboboat_full_crane_v1.py tests/test_roboboat_full_crane_v2.py` — **73 passed** (26 v1 and 47 v2). Cases exercise the real planner/realizer, missing-evidence ladder, observed witnesses, contact policy, timeout without result evidence, distinct public/configured limits, source/hash bindings, independently recomputed radial error/margin, altered plugin, evaluator-field rejection and real numeric/claim repairs.

No new provider answers, GPU captures or formally scored outputs were generated for v2. Before running this candidate on study data, record a distinct source-bound development intent and conduct an independent engineering/source audit. Source closure must include this adapter/catalog and all inherited temporal-certificate/planner/realizer dependencies. Answer completeness, measurement reliability and baseline fairness require subsequent reviewed development comparisons. Existing v1 limitation and repetitive-template wording are retained; this version does not claim that those presentation limitations are resolved.

An independent engineering review (`full_crane_v2_engineering_review.json`) found that dictionary-field validation accepted arbitrary task clocks and return-observation alignments while static contracts asserted a narrower temporal scope. Eight added regressions reproduced both gaps before repair. V2 now fails closed unless the sample clock is `ros-header-stamp` and any reference observation uses one of the two collector-defined alignment policies. Reference templates say “declared delivered reference observation” instead of implying temporal proximity to an action result; this wording also applies when a fixture timeout does not establish a terminal action result. V1 and all historical outputs are unchanged. The updated v1/v2 suite passes **81 tests**. The original review remains retained; repair review is a separate addendum.

Three additional adversarial regressions reproduced timeout packets that falsely supplied terminal-result scope. The collector uses timeout only when its result status is absent (`nav2_follow_path_fixture.py`); a cancellation request at the fixture deadline is not a canceled action result. V2 now rejects conflicting recorded result receipts or post-result intervals, while preserving a last-observed reference point and unknown docking. Injection/source-binding tests use faithful timeout packets. Updated adapter/runner suites: **96 passed** (v1, v2 and paired-response v2). No real v2 generation preceded these repairs.

The repair review identified a further source-semantic gap: arbitrary velocity-source declarations could be treated as measured motion. Nine red regressions reproduced this gap and unregistered measurement scope. V2 now requires `sampled-delivered-simulator-odometry` and, for every supplied velocity, `delivered-odometry-twist-body-to-odom`. Command traces cannot satisfy these contracts. These guards check declared semantics; source-bound collector/configuration provenance remains necessary to authenticate the supplied values. Updated suites: **105 passed**. Separate repair review remains necessary before actual source locking.
