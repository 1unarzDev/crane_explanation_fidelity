# Command trace validator — development candidate

`analysis/audit_roboboat_action_trace_v1.py` audits the proposed isolated v9 timing format. It is offline tooling and does not change technical admission, salvage prior failures or authorize scientific promotion. Twenty tests passed on construction traces, including conserved accepted, rejected, overwritten and pending receipts; missing callback/footer; payload corruption; altered receipt provenance; wrong gate decisions; future source timestamps; clock conversion; duplicate ordinals; and counter drift.

The validator requires a complete header/footer, no reported loss, writer failure, buffered events or payload bytes, an unsubscribed accepted-action observer, and matching written/enqueued/attempt counts. Ordinals must form an exact unique sequence. Receipt identities are source, episode and sequence; mailbox transitions must conserve them. Consumed receipts need gate attempts. Replayed policy checks retain the gate's rejection precedence and known-source fallback, and independently flag future source ticks. Exact command-topic callbacks retain raw seconds/nanoseconds and their conversion using the declared Unity float fixed step.

Post-apply callback events must match accepted gate receipts and application ticks one-for-one. Rejected receipts cannot have such callbacks. Payload bytes and encoding must be present and bounded. This proves only the recorded callback completion, not equality to independently observed original command payload or motor/physics response. For the ROS adapter, the apply callback sets desired velocity. Those limitations stay explicit in every output.

The instrumented worker snapshot is the prospective boundary for comparison with the worker result. Complete shutdown totals cannot be compared to an earlier worker result by trimming events until counts match. Each snapshot reconciles accepted/rejected/stale/cross-episode/duplicate counters with preceding decisions in its episode and unknown-source count with receipts. The worker comparison also checks accepted/known counts, source/receive mean and maximum lag, and maximum inter-application gap, in event-ordinal order. The metrics source samples these counters separately; it is not an atomic snapshot of background receive events. Actual snapshot races and command-timeout accounting need further qualification. Pending mailbox receipts are conserved, but their appropriateness for acquisition admission remains a prospective scientific decision.

Before use in collection: bind actual v9 source/build/schema, test actual serialized traces, audit every counter and receipt lifecycle, test resets and concurrency, verify clock mapping and logging overhead, and obtain independent review. No physical trace has yet passed this validator. Existing strict recording validity remains active. Confirmation and replication N are zero.
