# Simultaneous Unity startup benchmark v20

This fixed zero-N probe runs two exact shutdown-v17 players at distinct requested starts, worker IDs and seeds. ROS is disabled. Both retain the train-gpu profile, 640x360 window, original depth camera and signatures, .02 physics step and .04 catch-up cap. Each runs a20s benchmark after3s warmup, once, without retries. This is engineering evidence, not study collection or platform equivalence.

The parent waits for the shared legacy render gate before starting either player or the120s timeout. Its SH lock is compatible with the v4 child FPS leases; existing EX collectors remain isolated. Each child has its own nonce-owned executable/class, window/workspace/output, log, validation stream, frame audit and result namespace. The probe samples only its two nonce-owned client records. It requires distinct simultaneous live mapped windows and growing validation streams observed at least1s apart. Each terminal benchmark must independently pass original sensor/runtime/signature, seed/worker, startup receipt, scene path, clock and owned cleanup checks. Lease evidence must show at least two owners, a shared original FPS, and first/last release restoration. Empty-output engineering workers may also own leases; total ownership is not asserted to be exactly two.

Five tests reject sequential/static/one-growing-player evidence, duplicate window/PID/class/monitor/workspace identities, mismatched case identity, wrong seed, missing signatures, runtime/sensor/clock/pose/cleanup failures and timeout. These tests validate the engineering predicates; they do not establish actual concurrency.

The executed declaration is `artifacts/roboboat-parallel-player-startup-v20-003/declaration.json`, exact handle54945. Earlier-001 and-002 declarations were never physically launched and are retained with original source snapshots and explicit construction corrections: scene asset path rather than display name; at-least-two total FPS owners rather than exactly two. Neither correction used observed physical outcomes.

Even a passing result qualifies only concurrent rendered aquatic startup benchmarks and measured namespace/window/validation separation. Validation stream growth is evidence of active simulation sampling, not a full independent sensor-event trace. ROS domains, ports, action receipts, navigation and complete physical collection remain unqualified concurrently and need a separate once-only operational assay. No independent N, endpoint score, B4-vs-B2 effect, statistical power decision or confirmation freeze follows from this probe.
