# Shared-diagnostics architecture interface: preparation audit v1

This additive development tool implements the source/input preparation portion of `BASELINE_INTERFACE_DESIGN_V1.md`. It prepares an immutable common workspace for the proposed shared-marine-diagnostics agent. It selects no model, effort, baseline, endpoint, N or confirmatory method. Existing full-method reuse sources, declarations and outputs remain untouched. No real interface manifest has been generated automatically.

## Common public inputs

`shared_public_scope_v1.json` publishes the physical prerequisites currently enforced by full adapter `build_inputs`: ROS-header sample clock; sampled delivered simulator odometry; delivered body twist rotated into odom using the measured sample yaw; the two permitted reference alignments; fixture-monotonic result receipt versus ROS sample timestamps; and the first post-result sample anchoring the fixed public dwell. It states that fixture timeout means no terminal result was received, and that a cancellation request establishes neither cancellation completion nor a docking failure. Timeout cannot simultaneously carry a result receipt or nonempty post-result stream. Public goal, hull/berth geometry, requirements, uncertainty and contact policy remain the packet's exact values.

The public scope distinguishes configured thresholds from measured delivered observations, consumption and causation. Navigation thresholds do not replace the separate public docking requirements. It preserves positive partial sampled evidence, contact-completeness and continuous-time limits without exposing an approved-claim list, case-specific annotation inventory, plan or treatment repair procedure. The agent may run supplied renderers verbatim, reason, construct its own claims/plans, and verify or self-check any answer.

`analysis/roboboat_shared_public_scope_v1.py` provides neutral compatibility validation through existing packet validation plus these explicit public scope checks. It checks the exact supplied YAML against the visible configuration's digest/plugin/thresholds and rejects hidden evaluator/answer metadata in YAML. It returns only input-validity status, never a physical diagnosis, selected claims or answer. Both methods must use the identical staged inputs and public specification; this preparation does not change the existing full B4 implementation.

## Immutability and capabilities

Preparation accepts explicit visible packet/config paths and a fresh output namespace. It validates compatibility before creating the namespace, copies exact bytes into a read-only workspace, snapshots the full common source list, and records hashes for original inputs, snapshots, preparation code/tests and the public specification. Verification checks source/byte identities, exact common closure and input names, and rejects any undeclared workspace file. Repeated preparation cannot overwrite or reissue an existing namespace. The workspace contains no B4 outputs, intermediate plans, evaluator references or prior answers.

An offline test probe imports every legacy helper and uses a writable scratch directory outside the immutable workspace. This proves ordinary local Python imports and scratch writes in a construction fixture only. Actual transport inline Python, subprocess execution and isolated scratch under its read-only CLI sandbox remain pending; the tool does not promise the provider can write. Exact model/effort availability and provider/resource limits also remain pending. The tool makes no provider requests and stages no baseline prompt or selected operating point.

A future call declaration should reconcile compiled/deployed robot and Nav2 versions, audit mixed-source excerpts where needed, validate actual sandbox/tool capability and scratch isolation, bind the shared public scope for both methods, and then bind the prompt/model/effort/deadline panel before new responses. Existing unrestricted full-method reuse remains visible as a separate sensitivity. This candidate supports only the bounded architectural-interface interpretation; it does not establish superiority over an unrestricted agent given the full CRANE treatment.
